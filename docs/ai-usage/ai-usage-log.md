### Workflow

1. **I own every decision.** AI proposes options with trade-offs; I accept, change or reject; every decision is logged with the reason.
2. **Section-by-section analysis** of the brief: stated / implied / missing, with source tags (`Brief`, `AI`, `Own`) on every item, so the origin of each requirement stays visible.
3. **Stakeholder simulations** with local agents to find conflicts the brief hides (for example, who controls platforms).
4. **Spec-driven build with TDD for rules** (ADR-08): stories and acceptance criteria → contract → test names **approved by me** → agent implements → I review the diff → log.
5. **Agent steering through `CLAUDE.md`:** specs as source of truth, hard architecture and security rules, and a "stop and ask before…" list (dependencies, contract or rule changes, skipping tests, out-of-scope work).
6. **Open discussions** for big decisions (architecture, 8–9 Oct): I answer first, AI challenges, I decide.

**Important prompts (examples):**
- *"Before moving to discovery, let's make a timeline…"* (planning before analysis)
- *"Are we going test-driven or spec-driven?"* (led to the hybrid approach, ADR-08)
- *"Here there are several apps interconnected with user stories, so what approach do we need when creating epics?"* (led to goal-based epics and the apps × events matrix)
- *"Shall we have an open discussion on deciding architecture?"* (led to the ranked quality goals and Q1–Q6)
- Build prompt pattern: *"Implement US-O4 cancel and reinstate. Read CLAUDE.md, the story, R-14 and R-18 and contract §3.3 first. Show me the test names before writing code."*
